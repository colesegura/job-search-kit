# Keep progress connected to the next decision

Maintain one concise `private/current.md`: current objective, accepted/rejected interpretations, urgent lead or reply, permissions, next action, unresolved personal decision and recoverable draft locations. Detailed evidence belongs in the ledger and private source files. On resumption, answer the immediate question before restarting research.

When reviewing replies, use only authorized inbox access and distinguish acknowledgment, screening request, interview invitation, scheduled interview, conditional offer and confirmed offer. Record the message date and the exact next requirement. Verify the original applied-for role before preparing for an adjacent role. A scheduling proposal is not a booked interview; convert time zones explicitly.

Prepare interview guidance from duties and the applicant's substantiated experience. Identify missing skills honestly and discuss a training path rather than manufacturing a success story. The user should be able to explain every resume claim.

Compare offers by actual work, cash pay, realistic hours, deductions, room type, housing dates, season/closure gaps, transport, schedule, training, notice/commitment and unresolved terms. Do not substitute scenery or a headline package valuation for this check. Offer acceptance, resignation, travel purchases, contracts and sensitive screening are separate user decisions.

If the user requests recurring scouting, agree frequency, scope, budget and notification intent before configuring any available scheduling tool. Do not install schedules merely because this repository mentions refreshes. A refresh should return only new or materially changed opportunities, recheck priority leads, and advance a disclosed gap. It should stay quiet on unchanged states if that matches the user's intent. Research automation does not authorize applications or outreach.

Measure the funnel separately: sourced arrangements, eligible verified openings, completed applications, required unfinished steps, meaningful replies, interviews, offers and accepted arrangements. Track time and user effort where useful. A high application count is not success if fit or conversions are poor. Do not claim a method caused an offer merely because it preceded it.

If blockers stop conversion, stop multiplying equivalent blocked drafts. Present the short actionable blocker list and continue only independent useful work. On a handoff, preserve the next step and evidence limits instead of claiming the goal complete.
